# Orders — Implementation Plan

**Goal:** The shop starts saving orders. The owner gets a "הזמנות" admin area that replaces her per-bake-day Excel sheet. Product cards get a visible add-to-basket button.

**Vocabulary:** `GLOSSARY.md` (Order, Order line, Order number, Bake day, Due date, Cutoff, Pickup, Paid, Order status, Note, Day sheet, Bake list). Use these names in code.

**Decisions (from the 2026-10-22 design interview):**
- An order is saved when the customer taps send. WhatsApp/email still opens afterwards, with the order number in the message.
- Required: name + phone (Israeli mobile, `05XXXXXXXX`) + due date. Optional: note (≤500 chars). Pickup only, no address.
- The due date must be a bake day, chosen before the cutoff. **Assumed until the owner confirms:** Friday only, with a cutoff of the day before at 20:00 Israel time. Keep both as constants in one file.
- Statuses: `new` → `confirmed` → `ready`, or `cancelled`. Paid is a separate boolean. Cancelled orders are excluded from all totals.
- Order lines keep a snapshot of the product name + unit price. Server-side prices always come from `products`, never from the basket.
- The owner can edit any order and create manual orders (phone/chat). Customers can't edit.
- No Excel export, no delivery, no spam protection (mark it with a `shortcut:` comment).

**Guardrails:**
- Next.js **16.2.4**. Read `node_modules/next/dist/docs/` before writing routes, server actions, `searchParams`/`params` (they are Promises — `await` them). Copy existing patterns: `app/admin/(protected)/actions.ts` (`requireAdmin`), `app/admin/(protected)/products/[id]/edit/*`, `lib/products/queries.ts` (`server-only`), `lib/products/schema.ts` (Zod 4).
- No new npm dependencies. Use the `components/ui/*` primitives and existing Tailwind tokens. Hebrew RTL, mobile-first (375px).
- Time zone for "today", bake days and cutoff: `Asia/Jerusalem`.
- Do **not** commit. Do **not** touch the live database. There is no `.env.local`, so verify with `npx tsc --noEmit`, `npm run lint` and `npm run build`.

## Task 2 — Saving orders (DB + customer flow)

### 2a. Migration `supabase/migrations/0003_orders.sql`

```sql
create type public.order_status as enum ('new', 'confirmed', 'ready', 'cancelled');

create table public.orders (
  id             uuid primary key default gen_random_uuid(),
  order_number   bigint generated always as identity (start with 1001) unique,
  customer_name  text not null check (char_length(btrim(customer_name)) between 1 and 80),
  phone          text not null check (phone ~ '^05[0-9]{8}$'),
  due_date       date not null,
  note           text check (note is null or char_length(note) <= 500),
  status         public.order_status not null default 'new',
  is_paid        boolean not null default false,
  source         text not null default 'web' check (source in ('web', 'manual')),
  created_at     timestamptz not null default now()
);
create index orders_due_date_idx on public.orders (due_date);
create index orders_created_at_idx on public.orders (created_at desc);

create table public.order_lines (
  id            uuid primary key default gen_random_uuid(),
  order_id      uuid not null references public.orders (id) on delete cascade,
  product_id    uuid references public.products (id) on delete set null,
  product_name  text not null,
  unit_price    numeric(10, 2) not null check (unit_price >= 0),
  quantity      integer not null check (quantity between 1 and 99)
);
create index order_lines_order_id_idx on public.order_lines (order_id);

alter table public.orders enable row level security;
alter table public.order_lines enable row level security;
-- Admin (authenticated): full access. anon: NO table access, only place_order().
-- (create select/insert/update/delete policies `to authenticated using (true) with check (true)` for both tables, like 0001)
```

`place_order(p_name text, p_phone text, p_due_date date, p_note text, p_lines jsonb) returns table (order_number bigint, total numeric)` with `security definer`, `set search_path = public`:
- Validate: `p_lines` is a non-empty array of ≤30 `{product_id uuid, quantity int 1..99}`. Merge duplicate product ids by summing quantities, then re-check ≤99.
- `p_due_date >= (now() at time zone 'Asia/Jerusalem')::date`.
- Every product exists and `is_available`, otherwise `raise exception`.
- Insert the order (`source 'web'`, trimmed name, `nullif(btrim(p_note), '')`). Insert lines with `product_name`/`unit_price` selected **from products**. Return the number + total.
- `revoke all on function ... from public; grant execute ... to anon, authenticated;`

`admin_save_order(p_id uuid, p_order jsonb, p_lines jsonb) returns uuid` with `security invoker` (RLS applies, so authenticated only; also `revoke ... from public, anon; grant ... to authenticated`):
- `p_id` null → insert with `source 'manual'`. Otherwise update `customer_name, phone, due_date, note, status, is_paid`.
- Then delete that order's lines and insert `p_lines` (`[{product_id|null, product_name, unit_price, quantity}]`), all in the same function so it's one transaction. Reject empty lines.

### 2b. `lib/orders/`

## Task 3 — Admin "הזמנות"

- `app/admin/(protected)/layout.tsx`: add nav links מוצרים (`/admin`) | הזמנות (`/admin/orders`).
- `/admin/orders?date=YYYY-MM-DD` — **day sheet**. The default date is the first of `upcomingBakeDays`, or today if today is a bake day.
  - Header: the date (`formatBakeDay` + year), previous/next bake-day links, a date input, a print button (`window.print()`, small client component), and links to "כל ההזמנות" and "הזמנה חדשה".
  - **Bake list:** product name → total quantity over non-cancelled orders, sorted by product `display_order` when the product still exists.
  - **Customers:** one row/card per order (mobile = cards). Shows `#number`, name, `tel:` phone link, items as text (`חלת בריוש ×2, ...`), total, paid toggle, status `<select>` (auto-submits), and an edit link. Cancelled orders are greyed and at the bottom.
  - **Totals:** order count, grand total, paid, unpaid (non-cancelled only).
- `/admin/orders/all?status=&placed=today` — the list of all orders newest first, with status filter chips and a "placed today" filter.
- `/admin/orders/new` and `/admin/orders/[id]/edit` — a shared `OrderForm` (client) like `product-form.tsx`:
  - name, phone, due date (any date — the owner may override bake days), note, status, paid.
  - Lines editor: product `<select>` from `listProducts()` (including unavailable ones) + quantity + remove, plus "add line". Existing lines keep their snapshot name/price. A newly added line takes the product's current name/price.
  - Save → server action → `adminOrderSchema` → `rpc('admin_save_order')` → redirect to the day sheet for that due date.
  - Edit page: delete via `ConfirmDelete`.
- Server actions for status / paid / delete use `requireAdmin` + `revalidatePath`, like `toggleAvailable`.
- Print CSS: hide the nav and buttons when printing.
